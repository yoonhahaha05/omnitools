Descripción general y mecánica algorítmica

El primer dígito es la clase. 1xx significa que el servidor aceptó la solicitud y todavía está funcionando. 2xx significa éxito. 3xx significa que el cliente debería buscar en otra parte. 4xx significa que la solicitud es incorrecta o no está permitida. 5xx significa que el servidor falló. La página enumera los códigos estándar y una breve nota de depuración para cada uno.

Ejemplo resuelto. 200 está bien, el éxito habitual de GET. Se crea 201, el éxito habitual para un POST que creó un recurso. 301 es una redirección permanente. 302 es temporal. 404 significa que este servidor no tiene recursos en esa ruta. 401 significa que no estás autenticado. 403 significa que estás autenticado y aún no tienes permiso. 500 es un error del servidor no controlado. 502 y 504 apuntan a un proxy que no pudo obtener una buena respuesta desde arriba.

Ejemplos de uso

  • Una página faltante: 404 es el código. 401 y 403 son problemas diferentes.
  • Una puerta de entrada: 502 y 504 culpan al salto delante de la aplicación, no a la sintaxis de la URL del cliente.

Preguntas frecuentes

¿Cuál es la diferencia entre 401 y 403?

401 significa no autenticado (es necesario iniciar sesión), mientras que 403 significa autenticado pero no autorizado (acceso prohibido).

¿Es 200 una promesa de que el JSON es correcto?

El número 200 significa que la transacción HTTP se realizó correctamente. El cuerpo aún puede contener un error de aplicación.

¿Qué es 418?

418 no se utiliza en API reales. Estaba reservado a modo de broma en el RFC de la tetera. No construyas sobre ello.
