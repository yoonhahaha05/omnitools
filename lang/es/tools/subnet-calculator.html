Descripción general y mecánica algorítmica

Una calculadora de máscara de subred convierte una dirección como 192.168.1.10/24 en la dirección de red, el rango de host utilizable y la dirección de transmisión. La calculadora realiza cálculos de red bit a bit en tiempo real basados ​​en RFC 1519 (enrutamiento entre dominios sin clases) y RFC 791 (protocolo de Internet). Al convertir octetos decimales con puntos IPv4 estándar en enteros binarios de 32 bits, la calculadora aplica operaciones AND bit a bit con la máscara de subred para determinar la dirección base exacta de la red, la dirección de transmisión y la capacidad del host. En la ingeniería de nube moderna (AWS VPC, Google Cloud VPC, Azure VNet) y la arquitectura de red local, la asignación precisa de subred evita el agotamiento de las direcciones IP y los conflictos de superposición de enrutamiento. La aritmética se ejecuta en su navegador.

Ejemplo resuelto. Tome 192.168.1.10/24. El prefijo /24 significa que los primeros 24 bits son la red, por lo que la máscara es 255.255.255.0. La dirección de red es 192.168.1.0. La dirección de transmisión es 192.168.1.255. De las 256 direcciones del bloque, 254 se pueden asignar a hosts (192.168.1.1 a 192.168.1.254).

Ejemplos de uso

  • Infraestructura en la nube (AWS/GCP/Azure): Planificación de bloques CIDR de VPC que no se superpongan y asignaciones de subredes públicas/privadas para microservicios de varios niveles.
  • Ingeniería de redes empresariales: Configuración de listas de control de acceso (ACL) del enrutador, rangos de alcance de DHCP y resúmenes de enrutamiento OSPF/BGP.
  • Orquestación de DevOps y Docker: Definición de rangos de red de puentes y asignaciones de CIDR de pods de Kubernetes.

Equivalentes de código y terminal para el cálculo de subred

CLI de bash/terminal:
# Calculate subnet via ipcalc
ipcalc 192.168.1.0/24

# Inspect local interface subnet
ip -o -f inet addr show
Pitón 3:
import ipaddress

net = ipaddress.ip_network('192.168.1.0/24', strict=False)
print(f'Network: {net.network_address}')
print(f'Broadcast: {net.broadcast_address}')
print(f'Usable Hosts: {net.num_addresses - 2}')
print(f'Netmask: {net.netmask}')
JavaScript/Node.js:
// Node.js IP subnet calculation via bitwise ops
function cidrToMask(bits) {
  const mask = ~(2 ** (32 - bits) - 1);
  return [24, 16, 8, 0].map(s => (mask >>> s) & 255).join('.');
}
console.log(cidrToMask(24)); // '255.255.255.0'

Funciones

  • Cálculo instantáneo de direcciones de red, transmisión y rango de host
  • Admite todas las notaciones de prefijos CIDR desde /1 a /32
  • Incluye máscaras comodín y clasificación de IP pública/privada RFC 1918.

Pasos de uso

  1. Ingrese cualquier dirección IPv4 en el campo Dirección IP.
  2. Seleccione su prefijo CIDR (/1 a /32) en el menú desplegable o haga clic en un ajuste preestablecido rápido.
  3. Revise los límites de la red, el rango de IP utilizable y las capacidades del host.

Preguntas frecuentes

¿Por qué hay dos hosts utilizables menos que el total de direcciones IP?

En las subredes IPv4 estándar (/30 y mayores), la primera dirección se reserva como identificador de red y la dirección final se reserva como dirección de transmisión.

¿Cuál es la diferencia entre una máscara de subred y una máscara comodín?

Una máscara comodín es exactamente lo inverso (NO bit a bit) de una máscara de subred. Se utiliza ampliamente en listas de control de acceso (ACL) de Cisco y configuraciones de red OSPF.

¿Cuál es la diferencia entre dirección de red y dirección de transmisión?

La dirección de red es la IP más baja de la subred (todos los bits del host son 0) e identifica la subred misma. La dirección de transmisión es la IP más alta (todos los bits de host 1) utilizada para enviar paquetes a todos los hosts en esa subred. Ninguno de los dos se puede asignar a interfaces de red individuales.

¿Por qué AWS reserva 5 direcciones IP por subred en lugar de 2?

La red estándar reserva 2 direcciones (red y transmisión). AWS reserva 3 direcciones adicionales para el enrutador VPC (.1), el servidor DNS (.2) y el uso futuro del servicio interno (.3).

¿Mi configuración de IP privada está cargada en algún lugar?

Nunca. Los cálculos se ejecutan exclusivamente en la memoria del navegador mediante operaciones bit a bit de JavaScript. La arquitectura de su red interna permanece completamente segura.
