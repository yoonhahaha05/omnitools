Visão geral e mecânica algorítmica

O OmniTools HMAC Generator calcula códigos de autenticação de mensagens baseados em Hash de acordo com RFC 2104. O HMAC fornece integridade de dados criptográficos e verificação de autenticidade combinando uma função hash criptográfica (SHA-256, SHA-512, SHA-384 ou SHA-1) com uma chave secreta compartilhada por meio de passagens de preenchimento internas e externas ($H(K \oplus \text{opad} \parallel H(K \oplus \text{ipad} \paralelo m))$). Nossa implementação usa a API de criptografia da Web do navegador nativo (`window.crypto.subtle.sign`), garantindo desempenho criptográfico acelerado por hardware sem dependências de terceiros. Segredos confidenciais de assinatura de webhook, tokens de API e cabeçalhos de autorização nunca cruzam a Internet.

Exemplos de uso

  • Verificação de assinatura do webhook: Validação de cargas úteis de webhook recebidas de gateways de pagamento (Stripe, PayPal, Adyen) e plataformas de desenvolvedores (GitHub, Twilio).
  • Autenticação de solicitação de API: Geração de cabeçalhos AWS Signature versão 4 (SigV4) ou tokens de solicitação HMAC personalizados.
  • Integridade de dados e detecção de adulteração: Garantir que os arquivos de configuração transmitidos ou tokens de sessão não tenham sido modificados em trânsito.

Equivalentes de terminal e código para geração HMAC

Bash/Terminal CLI:
# HMAC-SHA256 in Bash via OpenSSL
echo -n "payload_data" | openssl dgst -sha256 -hmac "secret_key"
Pitão 3:
import hmac, hashlib

secret = b'secret_key'
msg = b'payload_data'
h = hmac.new(secret, msg, hashlib.sha256).hexdigest()
print('HMAC-SHA256:', h)
JavaScript/Node.js:
// Node.js HMAC
const crypto = require('crypto');
const hmac = crypto.createHmac('sha256', 'secret_key')
                   .update('payload_data')
                   .digest('hex');
console.log(hmac);

Recursos

  • Cálculo 100% do lado do cliente usando window.crypto.subtle nativo
  • Suporta algoritmos SHA-256, SHA-384, SHA-512 e SHA-1
  • Suporta codificações de saída Hexadecimal (minúsculas/maiúsculas) e Base64
  • Confidencial: sua API privada e chaves secretas de webhook nunca são transmitidas pela Internet

Como usar

  1. Selecione seu algoritmo de hash HMAC (por exemplo, SHA-256 para webhooks Stripe/GitHub).
  2. Insira sua chave secreta privada e a carga útil da mensagem.
  3. Escolha sua codificação de saída preferida (Hex ou Base64) e copie a assinatura.

Perguntas frequentes

É seguro colar minha chave secreta do webhook aqui?

Sim. Todos os cálculos são executados localmente na memória do seu navegador usando a sandbox da Web Crypto API. Zero pacotes de rede ou telemetria são transmitidos.

Para que é usado um HMAC?

Um HMAC (código de autenticação de mensagem baseado em hash) verifica a integridade dos dados e a autenticidade de uma mensagem entre duas partes usando um segredo compartilhado.

O que torna o HMAC mais seguro do que o hashing padrão?

Um hash padrão $H(key + message)$ é vulnerável a ataques de extensão de comprimento. O HMAC resolve isso por meio de sua construção de hashing de duas passagens aninhadas com pads internos e externos.

Como posso verificar uma assinatura de webhook com segurança?

Sempre use um algoritmo de comparação de tempo constante (como crypto.timingSafeEqual em Node.js ou hmac.compare_digest em Python) para evitar ataques de canal lateral de temporização.

As chaves secretas são salvas no cache do meu navegador?

Não. As chaves são mantidas na memória JavaScript transitória e são apagadas imediatamente quando você fecha ou atualiza a guia.
