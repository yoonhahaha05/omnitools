개요 및 알고리즘 메커니즘

OmniTools JWT 디코더는 RFC 7519에 따라 JSON 웹 토큰을 검사하고 압축을 풉니다. JWT는 점으로 구분된 Base64URL 인코딩 세 개의 세그먼트, 즉 헤더(알고리즘 및 토큰 유형), 페이로드(클레임, 제목, 발급자, 만료 및 사용자 정의 데이터) 및 암호화 서명으로 구성됩니다. 이 페이지는 헤더와 페이로드를 디코딩합니다. 서명을 확인하지 않습니다. 서명 확인에는 비밀 또는 공개 키가 필요하며 해당 키를 브라우저 도구에 붙여넣어서는 안 됩니다.

작업된 예입니다. 페이로드 세그먼트 eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ는 {"sub":"1234567890","name":"John Doe","iat":1516239022}로 디코딩됩니다. iat 값 1516239022는 2018-01-18 01:30:22 UTC입니다. 토큰이 있는 사람은 누구나 해당 주장을 읽을 수 있습니다. 서명은 발급자가 서명했다는 사실만 검증자에게 알려줍니다.

기술 사양

표준 청구키 이름TypeDescription검증 규칙

SubjectsubString고유한 주체 식별자(사용자 ID)사용자의 안정적인 식별자
Audienceaud문자열/배열토큰의 의도된 수신자백엔드 클라이언트 ID와 일치해야 합니다.
만료 시간expNumericDateUnix epoch 만료 타임스탬프현재 시간 > exp인 경우 토큰이 유효하지 않습니다.
발행일iatNumericDate발행 시 Unix 에포크 타임스탬프토큰 수명을 계산하는 데 사용됩니다.
이전에는 아님nbfNumericDate이 시간 이전에는 토큰을 수락할 수 없습니다.현재 시간 < nbf인 경우 토큰이 유효하지 않습니다.

사용 예

  • OAuth 2.0 및 OpenID Connect: ID 공급자(Auth0, Okta, Firebase, AWS Cognito)가 발행한 ID 토큰 및 액세스 토큰을 검사합니다.
  • 토큰 만료 감사: 인증 세션 중단 문제를 해결하려면 'exp'(만료) 및 'nbf'(이전 아님)를 확인하세요.
  • 역할 기반 액세스 확인: API 인증 헤더에 포함된 사용자 역할, 범위 및 클레임을 감사합니다.

JWT 검사에 해당하는 터미널 및 코드

배쉬/터미널 CLI:
# Decode JWT payload in terminal using jq
TOKEN="ey..."
echo $TOKEN | cut -d. -f2 | base64 -d 2>/dev/null | jq .
파이썬 3:
import json, base64

token = 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...'
payload_b64 = token.split('.')[1] + '=='
payload = json.loads(base64.urlsafe_b64decode(payload_b64))
print('JWT Claims:', json.dumps(payload, indent=2))
자바스크립트/Node.js:
// Browser client-side JWT payload decoder
function parseJwt(token) {
  const base64Url = token.split('.')[1];
  const base64 = base64Url.replace(/-/g, '+').replace(/_/g, '/');
  return JSON.parse(decodeURIComponent(escape(atob(base64))));
}

기능

  • 100% 비공개: 토큰은 제3자 서버로 전송되지 않습니다.
  • 헤더 및 페이로드 JSON 구조를 즉시 디코딩합니다.
  • 'exp' 타임스탬프 클레임에서 사람이 읽을 수 있는 만료 시간을 계산합니다.

사용 방법

  1. JWT 문자열을 토큰 입력 상자에 붙여넣습니다.
  2. 디코딩된 알고리즘 헤더를 검사하고 JSON 페이로드를 청구합니다.
  3. 토큰 유효성은 만료 배너를 확인하세요.

자주 묻는 질문

이 도구가 JWT 서명을 확인할 수 있나요?

서명 확인에는 비밀 또는 공개 인증서가 필요합니다. 클라이언트 측 도구는 개인 키를 요구하지 않고 클레임을 검사하고 디코딩합니다.

OmniTools가 내 JWT의 암호화 서명을 확인할 수 있나요?

디코더는 비밀 키 없이 헤더와 클레임을 검사할 수 있습니다. 서명 확인에는 개인 키나 공유 비밀이 필요하며, 이를 어떤 웹 브라우저 도구와도 공유해서는 안 됩니다.

여기에 실제 고객 토큰을 붙여넣어도 안전합니까?

예. OmniTools는 브라우저에서 100% 실행됩니다. 토큰 데이터는 원격 서버에서 전송, 기록 또는 캐시되지 않습니다.

내 토큰이 '만료됨'으로 표시되는 이유는 무엇입니까?

`exp` 클레임에는 Unix 타임스탬프가 포함되어 있습니다. OmniTools는 이를 장치의 현재 시계와 비교합니다. 컴퓨터의 시스템 시계가 왜곡된 경우 시간 동기화가 활성화되어 있는지 확인하세요.
