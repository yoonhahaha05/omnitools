개요 및 알고리즘 메커니즘

일부 문자는 눈에 보이는 공간을 차지하지 않습니다. U+200B는 너비가 0인 공간, U+200C는 너비가 0인 비조이너, U+200D는 너비가 0인 조이너, U+FEFF는 바이트 순서 표시입니다. U+00A0은 줄바꿈이 없는 공백으로 공백처럼 보이지만 검색 시 일반 공백과 일치하지 않습니다. 트로이 목마 소스 공격은 U+202E와 같은 bidi 컨트롤을 사용하여 컴파일러가 읽는 순서와 다른 순서로 코드를 표시합니다.

작업된 예입니다. "hel\u200Blo"라는 단어는 hello처럼 보이고 길이는 5가 아니라 6입니다. 너비가 0인 문자 스트립 다음에는 길이가 5이고 hello를 검색하면 일치합니다. U+FEFF로 시작하는 파일은 해당 표시를 잃습니다. 이는 동일한 스크립트에서 해시 또는 Shebang 검사가 실패할 때 중요합니다.

기술 사양

코드 포인트Name당신이 보는 것
U+200B너비가 0인 공간Nothing
U+200C너비가 0인 비결합자Nothing
U+200D너비가 0인 조이너Nothing
U+FEFF바이트 순서 표시Nothing
U+00A0휴식이 없는 공간감싸지 않는 공간
U+202E오른쪽에서 왼쪽으로 재정의뒤로 그려진 다음 텍스트

사용 예

  • 검색 미스: 가운데에 U+200B가 있는 hello는 정상적으로 보이며 표시가 제거될 때까지 일치하지 않습니다.
  • BOM: 스크립트 시작 부분의 U+FEFF가 제거되므로 처음으로 표시되는 문자가 파일의 실제 시작이 됩니다.

기능

  • U+200B, U+200C, U+200D, U+FEFF 감지
  • 완전한 비공개 클라이언트 측 구문 분석
  • 트로이목마 소스코드 삽입 방지

사용 방법

  1. 입력 필드에 텍스트를 붙여넣습니다.
  2. 보이지 않는 문자 카운터를 검토합니다.
  3. 지금 정리를 클릭합니다.

자주 묻는 질문

너비가 0인 공백의 원인은 무엇입니까?

서식 있는 텍스트 편집기, 채팅 애플리케이션 또는 PDF에서 텍스트를 복사하면 숨겨진 서식 바이트가 나타나는 경우가 많습니다.

이모티콘 피부색 조이너가 제거되나요?

U+200D는 이모티콘을 패밀리 시퀀스와 같은 하나의 문자 모양으로 결합하는 데에도 사용됩니다. 그것을 벗기면 해당 이모티콘이 분리됩니다.

카운터에는 일반 공간도 포함되어 있나요?

평범한 공간이 보입니다. 카운터는 클리너가 목표로 하는 숨겨진 문자와 금칙 문자를 위한 것입니다.
