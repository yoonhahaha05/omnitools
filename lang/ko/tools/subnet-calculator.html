서브넷 마스크 계산기

192.168.1.10/24와 같이 IP와 서브넷 마스크를 입력합니다. 네트워크, 사용 가능한 호스트 및 브로드캐스트 주소가 표시됩니다.

개요 및 알고리즘 메커니즘

서브넷 마스크 계산기는 192.168.1.10/24와 같은 주소를 네트워크 주소, 사용 가능한 호스트 범위 및 브로드캐스트 주소로 변환합니다. 계산기는 RFC 1519(클래스 없는 도메인 간 라우팅) 및 RFC 791(인터넷 프로토콜)을 기반으로 실시간 비트 네트워크 계산을 수행합니다. 표준 IPv4 점으로 구분된 10진수 옥텟을 32비트 이진 정수로 변환함으로써 계산기는 서브넷 마스크와 함께 비트 AND 연산을 적용하여 정확한 네트워크 기본 주소, 브로드캐스트 주소 및 호스트 용량을 결정합니다. 최신 클라우드 엔지니어링(AWS VPC, Google Cloud VPC, Azure VNet) 및 온프레미스 네트워크 아키텍처에서 정확한 서브넷 할당은 IP 주소 고갈 및 라우팅 중복 충돌을 방지합니다. 연산은 브라우저에서 실행됩니다.

작업된 예입니다. 192.168.1.10/24를 사용하세요. 접두사 /24는 처음 24비트가 네트워크임을 의미하므로 마스크는 255.255.255.0입니다. 네트워크 주소는 192.168.1.0입니다. 브로드캐스트 주소는 192.168.1.255입니다. 블록의 256개 주소 중 254개를 호스트(192.168.1.1~192.168.1.254)에 할당할 수 있습니다.

기술 사양

CIDR 접두사서브넷 마스크총 주소사용 가능한 호스트일반적인 사용 사례
/32255.255.255.25511(단일 호스트)호스트 경로, 방화벽 규칙
/30255.255.255.25242지점간 라우터 링크
/28255.255.255.2401614소규모 클러스터, DMZ 서브넷
/24255.255.255.0256254표준 사무실 LAN, AWS 서브넷
/20255.255.240.04,0964,094지역 클라우드 VPC 계층
/16255.255.0.065,53665,534기업 전체 네트워크 / VPC

사용 예

  • 클라우드 인프라(AWS/GCP/Azure): 다중 계층 마이크로서비스에 대해 겹치지 않는 VPC CIDR 블록 및 퍼블릭/프라이빗 서브넷 할당을 계획합니다.
  • 엔터프라이즈 네트워크 엔지니어링: 라우터 ACL(액세스 제어 목록), DHCP 범위 범위 및 OSPF/BGP 라우팅 요약을 구성합니다.
  • DevOps 및 Docker 오케스트레이션: 브리지 네트워크 범위 및 Kubernetes Pod CIDR 할당을 정의합니다.

서브넷 계산을 위한 터미널 및 해당 코드

배쉬/터미널 CLI:
# Calculate subnet via ipcalc
ipcalc 192.168.1.0/24

# Inspect local interface subnet
ip -o -f inet addr show
파이썬 3:
import ipaddress

net = ipaddress.ip_network('192.168.1.0/24', strict=False)
print(f'Network: {net.network_address}')
print(f'Broadcast: {net.broadcast_address}')
print(f'Usable Hosts: {net.num_addresses - 2}')
print(f'Netmask: {net.netmask}')
자바스크립트/Node.js:
// Node.js IP subnet calculation via bitwise ops
function cidrToMask(bits) {
  const mask = ~(2 ** (32 - bits) - 1);
  return [24, 16, 8, 0].map(s => (mask >>> s) & 255).join('.');
}
console.log(cidrToMask(24)); // '255.255.255.0'

기능

  • 네트워크, 브로드캐스트 및 호스트 범위 주소의 즉각적인 계산
  • /1에서 /32까지의 모든 CIDR 접두사 표기법을 지원합니다.
  • 와일드카드 마스크 및 RFC 1918 개인/공용 IP 분류 포함
  • 브라우저에서 실행되는 100% 클라이언트측 비트별 계산

사용 방법

  1. IP 주소 필드에 IPv4 주소를 입력합니다.
  2. 드롭다운에서 CIDR 접두사(/1~/32)를 선택하거나 빠른 사전 설정을 클릭합니다.
  3. 네트워크 경계, 사용 가능한 IP 범위 및 호스트 용량을 검토합니다.

자주 묻는 질문

총 IP 주소보다 사용 가능한 호스트가 2개 적은 이유는 무엇입니까?

표준 IPv4 서브넷(/30 이상)에서는 첫 번째 주소가 네트워크 식별자로 예약되고 마지막 주소가 브로드캐스트 주소로 예약됩니다.

서브넷 마스크와 와일드카드 마스크의 차이점은 무엇입니까?

와일드카드 마스크는 서브넷 마스크의 정반대(비트 단위 NOT)입니다. 이는 Cisco ACL(액세스 제어 목록) 및 OSPF 네트워크 구성에서 널리 사용됩니다.

네트워크 주소와 브로드캐스트 주소의 차이점은 무엇입니까?

네트워크 주소는 서브넷의 가장 낮은 IP(모든 호스트 비트 0)이며 서브넷 자체를 식별합니다. 브로드캐스트 주소는 해당 서브넷의 모든 호스트에 패킷을 보내는 데 사용되는 가장 높은 IP(모든 호스트 비트 1)입니다. 개별 네트워크 인터페이스에는 둘 다 할당할 수 없습니다.

AWS가 서브넷당 2개가 아닌 5개의 IP 주소를 예약하는 이유는 무엇입니까?

표준 네트워킹은 2개의 주소(네트워크 및 브로드캐스트)를 예약합니다. AWS는 VPC 라우터(.1), DNS 서버(.2) 및 향후 내부 서비스 사용(.3)을 위해 추가로 3개의 주소를 예약합니다.

내 개인 IP 구성이 어디에나 업로드되나요?

절대. 계산은 JavaScript 비트 연산을 통해 브라우저 메모리에서만 실행됩니다. 내부 네트워크 아키텍처는 완전히 안전하게 유지됩니다.
