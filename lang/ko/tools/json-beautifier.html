개요 및 알고리즘 메커니즘

OmniTools JSON Beautifier, Validator 및 Formatter는 RFC 8259 사양에 따라 원시 JSON 문서를 구문 분석합니다. 클라이언트 메모리에서 추상 구문 표현을 구성하고, 문자열 이스케이프를 정규화하고, 구조적 구문 오류(예: 인용되지 않은 키, 후행 쉼표 또는 누락된 괄호)를 감지하고 구성 가능한 2-공백, 4-공백 또는 탭 들여쓰기를 사용하여 데이터를 다시 직렬화합니다. 포맷터는 브라우저의 JSON.parse 및 JSON.stringify를 사용합니다. 주석, 작은따옴표 키 또는 후행 쉼표는 유효한 JSON이 아니기 때문에 허용되지 않습니다.

작업된 예입니다. {"name":"Ada","ok":true}를 붙여넣고 2칸 들여쓰기를 선택합니다. 결과는 다음과 같습니다.

{ "이름": "에이다", "확인": 참 }

{"name":"Ada",}와 같은 후행 쉼표는 거부됩니다. 쉼표를 제거하고 다시 형식을 지정하세요.

기술 사양

JSON 데이터 유형유효한 예잘못된 함정RFC 8259 규칙
String"예"'작은따옴표'큰따옴표(\"...\")를 사용해야 합니다.
Number42, -3.14, 1e60123, NaN, 인피니티앞에 0이 없습니다. NaN/무한대는 금지됩니다.
Boolean사실, 거짓참, 거짓, 1, 0소문자 리터럴이어야 합니다.
Nullnull없음, 정의되지 않음소문자 리터럴 null만 유효합니다.
Array[1, 2, 3][1, 2, 3,]후행 쉼표는 엄격하게 유효하지 않습니다.
Object{"키": "발"}{키: '발'}키는 큰따옴표로 묶인 문자열이어야 합니다.

사용 예

  • API 디버깅 및 페이로드 검사: 프로덕션 서버에서 반환된 읽을 수 없는 축소된 REST 및 GraphQL JSON 페이로드의 형식을 지정합니다.
  • 구성 파일 유효성 검사: 복잡한 구성 파일(package.json, tsconfig.json, Kubernetes ConfigMaps)을 정리하고 린트합니다.
  • 데이터 위생 및 축소: 불필요한 공백과 캐리지 리턴을 제거하여 페이로드 전송 크기를 최적화합니다.

JSON 형식화에 해당하는 터미널 및 코드

배쉬/터미널 CLI:
# Pretty print JSON using jq
cat data.json | jq .

# Format JSON using Python CLI
python3 -m json.tool data.json
파이썬 3:
import json

raw = '{"name":"omnitools","status":200}'
parsed = json.loads(raw)
print(json.dumps(parsed, indent=2, sort_keys=True))
자바스크립트/Node.js:
// JavaScript native JSON formatting
const raw = '{"tool":"json-beautifier","local":true}';
const formatted = JSON.stringify(JSON.parse(raw), null, 2);
console.log(formatted);

기능

  • 100% 클라이언트측
  • 제로 레이턴시

사용 방법

  1. JSON을 편집기에 붙여넣습니다.
  2. 들여쓰기하려면 Beautify를 클릭하고 압축하려면 Minify를 클릭하세요.
  3. 결과를 복사합니다.

자주 묻는 질문

JSON에서 후행 쉼표가 유효합니까?

아니요, 표준 JSON 사양에서는 후행 쉼표를 금지합니다.

JSON이 후행 쉼표를 금지하는 이유는 무엇입니까?

RFC 8259는 모든 프로그래밍 언어와 이전 레거시 파서에서 명확한 구문 분석을 보장하기 위해 후행 쉼표를 엄격히 금지합니다.

OmniTools는 충돌 없이 대용량 JSON 파일의 형식을 지정할 수 있나요?

예. 작업은 네트워크 시간 초과 없이 로컬 브라우저 메모리에서 직접 실행되므로 사용 가능한 RAM에 따라 최대 수십 메가바이트까지 파일을 편안하게 포맷할 수 있습니다.

OmniTools는 주석이 포함된 JSON5 또는 JSON을 지원합니까?

표준 JSON은 주석(// 또는 /* */)을 엄격히 허용하지 않습니다. 우리의 포맷터는 공식 RFC 8259 표준을 준수하여 모든 프로덕션 파서에서 출력이 유효하도록 보장합니다.
