Überblick und algorithmische Mechanik

Der Formatierer schreibt erkannte Schlüsselwörter in Großbuchstaben und fügt Hauptsätze in eigene Zeilen ein. SELECT, FROM, WHERE, JOIN, GROUP BY, ORDER BY und LIMIT sind die üblichen Pausen. Es stellt keine Verbindung zu einer Datenbank her und überprüft nicht, ob Tabellen vorhanden sind. Von Ihnen zitierte Bezeichner bleiben so, wie Sie sie geschrieben haben.

Ausgearbeitetes Beispiel. „select id, name from user where active = 1 order by name“ wird zu einer SELECT-Liste, einer FROM-Zeile, einer WHERE-Zeile und einer ORDER BY-Zeile mit den Schlüsselwörtern in Großbuchstaben. Ein String-Literal „select“ wird nicht in Großbuchstaben geschrieben, da es sich um Daten handelt. Ein fehlendes Komma bleibt auch nach der Formatierung ein fehlendes Komma.

Anwendungsbeispiele

  • Eine einzeilige Abfrage: SELECT, FROM, WO und ORDER BY jedes Land auf seiner eigenen Linie.
  • Ein Schlüsselwort innerhalb einer Zeichenfolge: 'select' bleibt kleingeschrieben.

Funktionen

  • Großschreibung von Standard-SQL-Schlüsselwörtern (SELECT, FROM, WHERE, JOIN)
  • Fügt logische Klauselzeilenumbrüche hinzu
  • Unterstützt PostgreSQL-, MySQL- und SQLite-Dialektsyntax

So geht's

  1. Fügen Sie eine unformatierte SQL-Anweisung ein.
  2. Klicken Sie auf SQL formatieren.
  3. Kopieren Sie das Ergebnis.

Häufige Fragen

Führt dies Abfragen für meine Datenbank durch?

Nein, es handelt sich ausschließlich um einen clientseitigen String-Formatierer ohne Datenbankverbindungen.

Werden dadurch fehlende Kommas hinzugefügt oder ein fehlerhafter Join behoben?

Nein. Es werden nur Leerzeichen und die Groß-/Kleinschreibung von Schlüsselwörtern geändert.

Aus welchen Dialekten stammen die Schlüsselwörter?

Der gemeinsame Kern, der von PostgreSQL, MySQL und SQLite verwendet wird. Als Bezeichner bleiben herstellerspezifische Funktionen übrig.
