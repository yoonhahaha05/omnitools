Überblick und algorithmische Mechanik

Der OmniTools HMAC-Generator berechnet Hash-basierte Nachrichtenauthentifizierungscodes gemäß RFC 2104. HMAC ermöglicht die Überprüfung der Integrität und Authentizität kryptografischer Daten durch die Kombination einer kryptografischen Hash-Funktion (SHA-256, SHA-512, SHA-384 oder SHA-1) mit einem gemeinsamen geheimen Schlüssel durch innere und äußere Fülldurchgänge ($H(K \oplus \text{opad} \parallel H(K \oplus \text{ipad} \parallel m))$). Unsere Implementierung verwendet die native Browser-Web-Kryptografie-API („window.crypto.subtle.sign“) und gewährleistet so eine hardwarebeschleunigte kryptografische Leistung ohne Abhängigkeiten von Drittanbietern. Sensible Webhook-Signaturgeheimnisse, API-Tokens und Autorisierungsheader gelangen niemals ins Internet.

Anwendungsbeispiele

  • Überprüfung der Webhook-Signatur: Validierung eingehender Webhook-Nutzlasten von Zahlungsgateways (Stripe, PayPal, Adyen) und Entwicklerplattformen (GitHub, Twilio).
  • API-Anfrageauthentifizierung: Generieren von AWS Signature Version 4 (SigV4)-Headern oder benutzerdefinierten HMAC-Anfragetokens.
  • Datenintegrität und Manipulationserkennung: Sicherstellen, dass übertragene Konfigurationsdateien oder Sitzungstoken während der Übertragung nicht geändert wurden.

Terminal- und Codeäquivalente für die HMAC-Generierung

Bash/Terminal-CLI:
# HMAC-SHA256 in Bash via OpenSSL
echo -n "payload_data" | openssl dgst -sha256 -hmac "secret_key"
Python 3:
import hmac, hashlib

secret = b'secret_key'
msg = b'payload_data'
h = hmac.new(secret, msg, hashlib.sha256).hexdigest()
print('HMAC-SHA256:', h)
JavaScript / Node.js:
// Node.js HMAC
const crypto = require('crypto');
const hmac = crypto.createHmac('sha256', 'secret_key')
                   .update('payload_data')
                   .digest('hex');
console.log(hmac);

Funktionen

  • 100 % clientseitige Berechnung mit nativem window.crypto.subtle
  • Unterstützt die Algorithmen SHA-256, SHA-384, SHA-512 und SHA-1
  • Unterstützt Hexadezimal- (Klein-/Großbuchstaben) und Base64-Ausgabekodierungen
  • Vertraulich: Ihre privaten API- und Webhook-Geheimschlüssel werden niemals über das Internet übertragen

So geht's

  1. Wählen Sie Ihren HMAC-Hash-Algorithmus aus (z. B. SHA-256 für Stripe/GitHub-Webhooks).
  2. Geben Sie Ihren privaten Geheimschlüssel und die Nachrichtennutzlast ein.
  3. Wählen Sie Ihre bevorzugte Ausgabekodierung (Hex oder Base64) und kopieren Sie die Signatur.

Häufige Fragen

Ist es sicher, meinen geheimen Webhook-Schlüssel hier einzufügen?

Ja. Alle Berechnungen werden mithilfe der Web Crypto API-Sandbox lokal in Ihrem Browserspeicher ausgeführt. Es werden keine Netzwerkpakete oder Telemetriedaten übertragen.

Wofür wird ein HMAC verwendet?

Ein HMAC (Hash-based Message Authentication Code) überprüft sowohl die Datenintegrität als auch die Authentizität einer Nachricht zwischen zwei Parteien mithilfe eines gemeinsamen Geheimnisses.

Was macht HMAC sicherer als Standard-Hashing?

Ein Standard-Hash $H(key + message)$ ist anfällig für Längenerweiterungsangriffe. HMAC löst dieses Problem durch seine verschachtelte Zwei-Pass-Hashing-Konstruktion mit inneren und äußeren Pads.

Wie kann ich eine Webhook-Signatur sicher überprüfen?

Verwenden Sie immer einen Vergleichsalgorithmus mit konstanter Zeit (z. B. crypto.timingSafeEqual in Node.js oder hmac.compare_digest in Python), um Timing-Seitenkanalangriffe zu verhindern.

Werden geheime Schlüssel in meinem Browser-Cache gespeichert?

Nein. Schlüssel werden im vorübergehenden JavaScript-Speicher gehalten und sofort gelöscht, wenn Sie die Registerkarte schließen oder aktualisieren.
