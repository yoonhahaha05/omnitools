Überblick und algorithmische Mechanik

Der OmniTools JWT Decoder prüft und entpackt JSON-Web-Tokens gemäß RFC 7519. Ein JWT besteht aus drei durch Punkte getrennten Base64URL-codierten Segmenten: dem Header (Algorithmus und Token-Typ), der Nutzlast (Ansprüche, Betreff, Aussteller, Ablauf und benutzerdefinierte Daten) und der kryptografischen Signatur. Diese Seite dekodiert den Header und die Nutzlast. Die Signatur wird nicht überprüft. Für eine Signaturprüfung ist der geheime oder öffentliche Schlüssel erforderlich. Dieser Schlüssel sollte nicht in ein Browser-Tool eingefügt werden.

Ausgearbeitetes Beispiel. Das Nutzlastsegment eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ dekodiert zu {"sub": "1234567890", "name": "John Doe", "iat": 1516239022}. Der iat-Wert 1516239022 ist 18.01.2018 01:30:22 UTC. Jeder, der das Token besitzt, kann diese Behauptungen lesen. Die Signatur teilt einem Prüfer lediglich mit, dass der Aussteller sie unterzeichnet hat.

Anwendungsbeispiele

  • OAuth 2.0 und OpenID Connect: Überprüfung von ID-Tokens und Zugriffstokens, die von Identitätsanbietern (Auth0, Okta, Firebase, AWS Cognito) ausgestellt wurden.
  • Token-Ablaufprüfungen: Überprüfen der Angaben „exp“ (Ablauf) und „nbf“ (nicht vorher), um das Abbrechen von Authentifizierungssitzungen zu beheben.
  • Rollenbasierte Zugriffsüberprüfung: Überwachen von Benutzerrollen, -bereichen und -ansprüchen, die in API-Autorisierungsheadern eingebettet sind.

Terminal- und Codeäquivalente für die JWT-Inspektion

Bash/Terminal-CLI:
# Decode JWT payload in terminal using jq
TOKEN="ey..."
echo $TOKEN | cut -d. -f2 | base64 -d 2>/dev/null | jq .
Python 3:
import json, base64

token = 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...'
payload_b64 = token.split('.')[1] + '=='
payload = json.loads(base64.urlsafe_b64decode(payload_b64))
print('JWT Claims:', json.dumps(payload, indent=2))
JavaScript / Node.js:
// Browser client-side JWT payload decoder
function parseJwt(token) {
  const base64Url = token.split('.')[1];
  const base64 = base64Url.replace(/-/g, '+').replace(/_/g, '/');
  return JSON.parse(decodeURIComponent(escape(atob(base64))));
}

Funktionen

  • 100 % privat: Token werden niemals an einen Server eines Drittanbieters gesendet
  • Dekodiert Header- und Payload-JSON-Strukturen sofort
  • Berechnet die für Menschen lesbare Ablaufzeit aus dem Zeitstempelanspruch „exp“.

So geht's

  1. Fügen Sie Ihre JWT-Zeichenfolge in das Token-Eingabefeld ein.
  2. Überprüfen Sie den dekodierten Algorithmus-Header und beanspruchen Sie die JSON-Nutzlast.
  3. Überprüfen Sie das Ablaufbanner auf die Gültigkeit des Tokens.

Häufige Fragen

Kann dieses Tool die JWT-Signatur überprüfen?

Für die Signaturüberprüfung ist das geheime oder öffentliche Zertifikat erforderlich. Clientseitige Tools prüfen und entschlüsseln die Ansprüche, ohne dass Ihre privaten Schlüssel erforderlich sind.

Kann OmniTools die kryptografische Signatur meines JWT überprüfen?

Decoder können den Header und die Ansprüche ohne geheimen Schlüssel prüfen. Für die Signaturüberprüfung ist der private Schlüssel oder das gemeinsame Geheimnis erforderlich, das Sie niemals mit einem Webbrowser-Tool teilen sollten.

Ist es sicher, hier echte Kunden-Token einzufügen?

Ja. OmniTools läuft zu 100 % in Ihrem Browser. Es werden niemals Token-Daten auf einem Remote-Server übertragen, protokolliert oder zwischengespeichert.

Warum wird auf meinem Token „Abgelaufen“ angezeigt?

Der Anspruch „exp“ enthält einen Unix-Zeitstempel. OmniTools vergleicht dies mit der aktuellen Uhr Ihres Geräts. Wenn die Systemuhr Ihres Computers falsch läuft, stellen Sie sicher, dass die Zeitsynchronisierung aktiviert ist.
