Überblick und algorithmische Mechanik

Der OmniTools Base64 Encoder und Decoder wandelt Binär- und String-Daten gemäß RFC 4648 in ASCII-Radix-64-Darstellungen um. Die Base64-Kodierung nimmt 3 Byte Binärdaten (24 Bit) und ordnet sie in 4 druckbare ASCII-Zeichen (jeweils 6 Bit) zu, die aus einer Indextabelle mit 64 Zeichen (A–Z, a–z, 0–9, +, /) ausgewählt werden. Wenn die Anzahl der Eingabebytes nicht durch 3 teilbar ist, werden Füllzeichen „=“ angehängt, um die Ausrichtung beizubehalten. Standard-JavaScript btoa und atob werfen Zeichen außerhalb von Latin-1 auf. Dieser Encoder wandelt den Text zunächst in UTF-8-Bytes um, also akzentuierte Buchstaben und Emoji-Roundtrip. Im URL-sicheren Modus wird + durch - und / durch _ ersetzt.

Ausgearbeitetes Beispiel. Verschlüsseln Sie das Wort OmniTools. Das Ergebnis ist T21uaVRvb2xz. Die Dekodierung dieser Zeichenfolge gibt OmniTools zurück. Das Wort besteht aus 9 Bytes, was gleichmäßig durch 3 geteilt wird, daher gibt es kein =-Auffüllen.

Anwendungsbeispiele

  • Webentwicklung und APIs: Codierung der Autorisierungsheader für die Basisauthentifizierung („Authorization: Basic `).
  • Daten-URIs und Inline-Assets: Einbetten kleiner SVG-Symbole, Schriftarten und Bilder direkt in CSS- und HTML-Dateien.
  • Datenserialisierung: Sichere Übertragung binärer Nutzdaten über Nur-Text-Übertragungskanäle (JSON, XML, E-Mail).

Terminal- und Codeäquivalente für Base64-Kodierung und -Dekodierung

Bash/Terminal-CLI:
# Encode string to Base64 in Bash
echo -n "OmniTools" | base64

# Decode Base64 string
echo "T21uaVRvb2xz" | base64 --decode
Python 3:
import base64

# Unicode-safe Base64 in Python
encoded = base64.b64encode('OmniTools 🚀'.encode('utf-8')).decode('ascii')
decoded = base64.b64decode(encoded).decode('utf-8')
print(f'Encoded: {encoded} -> Decoded: {decoded}')
JavaScript / Node.js:
// Node.js Buffer Base64
const str = 'OmniTools 🚀';
const b64 = Buffer.from(str, 'utf-8').toString('base64');
const original = Buffer.from(b64, 'base64').toString('utf-8');
console.log({ b64, original });

Funktionen

  • Vollständige UTF-8-Unterstützung für Akzentzeichen, Emojis und Nicht-ASCII-Text
  • Der URL-sichere Modus ersetzt „+“ und „/“ durch „-“ und „_“.
  • Bidirektionale sofortige Kodierung und Dekodierung

Häufige Fragen

Was ist URL-sicheres Base64?

URL-sicheres Base64 ersetzt „+“ durch „-“ und „/“ durch „_“ und entfernt abschließende Füllzeichen „=“.

Verschlüsselt Base64 meine Daten?

Nein. Base64 ist ein Kodierungsschema, KEINE Verschlüsselung. Jeder kann einen Base64-String sofort dekodieren. Verwenden Sie Base64 niemals allein zum Schutz von Passwörtern, Schlüsseln oder vertraulichen Anmeldeinformationen.

Warum erhöht Base64 die Datengröße um ~33 %?

Base64 stellt 3 Bytes (24 Bit) Daten mit 4 ASCII-Zeichen (32 Bit) dar. Dieses Verhältnis von 4:3 führt natürlich zu einer Overhead-Erweiterung von etwa 33,3 %.

Kann ich Binärdateien sicher kodieren?

Ja. Unsere clientseitige FileReader-API liest Binärdateien direkt in Uint8Array-Puffer und gewährleistet so Byte-für-Byte-Wiedergabetreue ohne Datenverlust.
