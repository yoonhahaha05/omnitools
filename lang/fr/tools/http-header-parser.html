Présentation générale et mécanique algorithmique

Collez le bloc d'en-tête brut, un champ par ligne, sous la forme Nom : valeur. La page se divise sur les premiers deux-points et répertorie les paires. L'audit recherche ensuite un court ensemble d'en-têtes de réponse qui modifient le comportement du navigateur : Strict-Transport-Security, Content-Security-Policy, X-Frame-Options ou un ancêtre de trame CSP, X-Content-Type-Options, Referrer-Policy et Permissions-Policy.

Exemple travaillé. Un bloc qui contient Strict-Transport-Security : max-age=31536000 ; includeSubDomains et X-Content-Type-Options : nosniff les enregistre comme étant présents. Un bloc sans Content-Security-Policy est signalé comme manquant. L'audit ne demande pas l'URL. Il ne lit que ce que vous avez collé. Un bloc d'en-tête de requête de curl -I est la ligne d'état de la réponse plus les en-têtes. La ligne d’état n’est pas une paire Nom : valeur.

Exemples d'usage

  • HSTS: max-age=31536000 correspond à un an en secondes.
  • Un CSP manquant : L’audit marque l’absence de politique de sécurité du contenu. Il n'invente pas de politique.

Fonctions

  • Analyse les en-têtes de réponse HTTP multilignes dans des tables clé-valeur structurées
  • Audit de sécurité automatisé vérifiant 6 en-têtes de défense OWASP essentiels
  • Évalue les défenses Strict-Transport-Security (HSTS), Content-Security-Policy (CSP) et Clickjacking
  • Fonctionne à 100 % dans votre navigateur sans transmission réseau

Mode d'emploi

  1. Collez les en-têtes HTTP bruts copiés depuis curl -I, le navigateur DevTools ou Postman.
  2. Examinez le tableau des en-têtes structurés et le score de l'audit de sécurité.
  3. Identifiez les en-têtes manquants et mettez en œuvre les atténuations OWASP suggérées.

Questions fréquentes

Quel est l’en-tête de sécurité HTTP le plus critique ?

La politique de sécurité du contenu (CSP) et la sécurité stricte du transport (HSTS) sont largement considérées comme les plus vitales pour prévenir les attaques par déclassement des protocoles XSS et man-in-the-middle.

Comment extraire les en-têtes HTTP de mon navigateur ?

Ouvrez le navigateur DevTools (F12), accédez à l'onglet Réseau, actualisez la page, cliquez sur la demande de document principale et affichez la section En-têtes de réponse.

Un score élevé signifie-t-il que le site est sécurisé ?

Cela signifie que ces en-têtes étaient dans la pâte. Un CSP faible compte toujours comme présent. Lisez la directive, pas seulement la coche.

Comment copier les en-têtes de réponse ?

curl -I https://example.com, ou DevTools, Réseau, la demande de document, En-têtes de réponse. Copiez les lignes, pas le corps HTML.
